# Free-tier deployment: Render (API + database) and Vercel (web apps)

This is the ₹0 path. It needs accounts that only the project owner can create, so every
step below is done by hand in the providers' dashboards. Nothing here is verified until
you open the deployed URLs and the checks at the end pass.

| Piece | Host | Plan | Config in repo |
|---|---|---|---|
| FastAPI backend | Render web service (Docker) | Free | `render.yaml` |
| PostgreSQL 16 + PostGIS | Render Postgres | Free | `render.yaml` |
| Commuter web app | Vercel | Hobby (free) | `frontend/vercel.json` |
| Admin dashboard | Vercel (second project) | Hobby (free) | `frontend4admin/vercel.json` |
| Traffic collector | GitHub Actions schedule | Free (public repo) | `.github/workflows/collector.yml` |
| Routing | Public FOSSGIS OSRM servers | Free, fair use | env vars in `render.yaml` |
| Sign-in | Firebase Authentication (optional) | Spark (free) | env vars |
| Live traffic | TomTom (optional) | Free tier, 2,500 calls/day | env var |

## Free-tier limits you will notice

- **Cold starts.** A free Render web service sleeps after about 15 minutes without traffic.
  The next request wakes it, which takes around a minute. The web app shows a loading or
  error state until then.
- **Database expiry.** Render's free Postgres expires 30 days after creation (Render emails
  before deleting it). To keep data, upgrade it, or move to a free PostGIS-capable host such
  as Neon or Supabase and set `DATABASE_URL` on the web service to that URL instead.
- **512 MB RAM** for the API. The app loads scikit-learn and pandas at startup. Watch
  the Render metrics after the first deploy.
- **Routing.** OSRM needs a pre-built Bengaluru graph and more memory than any free web
  plan offers, so the API uses the public servers at `routing.openstreetmap.de` (car, foot,
  bike). These are shared and rate-limited, so `render.yaml` caps each route request at
  1 + 4 OSRM calls, made one at a time. That gives fewer alternative routes than the full
  stack, which makes up to 11 calls per route. These servers do not support OSRM `exclude`,
  so the "avoid tolls/motorways/ferries" options are hidden (`OSRM_EXCLUDE_SUPPORTED=false`).
  If you send too many requests, the servers block you temporarily, and routing returns
  "routing engine unavailable" until the block lifts. To get full routing back, run your own
  OSRM (`docker-compose.yml`, `infrastructure/osrm/`) on any host and point `OSRM_URL`,
  `OSRM_FOOT_URL` and `OSRM_BICYCLE_URL` at it.
- **No always-on collector.** Render's background workers and cron jobs are paid. The
  collector runs as a GitHub Actions job every 30 minutes (`--once` sweeps). GitHub can delay
  scheduled runs, and it pauses schedules after 60 days without repository activity. The daily
  model retrain that the compose collector did is not part of this path.

## 1. Push the code

Render and Vercel deploy from GitHub. Push branch `v2-build`, and merge it into `main` if you
want `main` to be what's deployed. In each dashboard, pick the branch you pushed.

## 2. Backend and database on Render

1. Sign in at https://dashboard.render.com with GitHub, and give Render access to
   `bengaluru-pulse-lite`.
2. **New → Blueprint**, choose the repository and branch. Render reads `render.yaml` and
   proposes `bengaluru-pulse-api` (web, free) and `bengaluru-pulse-db` (Postgres, free) in
   Singapore.
3. Fill in the values Render asks for:
   - `CORS_ORIGINS`: your Vercel URLs, comma-separated. You don't know them yet, so put
     `http://localhost:3000` for now and update it in step 4.
   - `CORS_ORIGIN_REGEX`: optional, to allow Vercel preview URLs, for example
     `^https://bengaluru-pulse(-[a-z0-9-]+)?\.vercel\.app$`. Leave it empty to allow only the
     listed origins.
   - `TOMTOM_API_KEY`: optional (https://developer.tomtom.com, free key). Empty means no live
     traffic.
   - `FIREBASE_PROJECT_ID`: optional. Empty means built-in email/password sign-in only.
4. **Apply.** The first build takes several minutes. On start, the container runs
   `alembic upgrade head`, which creates the PostGIS and pg_trgm extensions and the
   tables, then serves on Render's `$PORT`.
5. Note the service URL, for example `https://bengaluru-pulse-api.onrender.com`, and check
   `https://<api>/health` (should return `{"status":"ok",...}`) and `https://<api>/health/ready`.
6. `JWT_SECRET` is generated by Render. Keep it stable: changing it signs everyone out.

### Create the first admin

Sign up through the web app, then promote that account. Render's free plan has no Shell,
so run this from your PC (in `backend/`, with the project venv) against the **External
Database URL** from the Render database page:

```
cd backend
set DATABASE_URL=<External Database URL>      (PowerShell: $env:DATABASE_URL="<...>")
python -m auth.bootstrap --email <you@domain> --promote
```

## 3. Web apps on Vercel

Do this twice, once per app.

1. https://vercel.com → **Add New → Project** → import `bengaluru-pulse-lite`.
2. **Root Directory**: `frontend` (commuter app) or `frontend4admin` (admin dashboard).
   Vercel reads `vercel.json` in that folder (Create React App, SPA fallback).
3. **Environment Variables** (Production and Preview):
   - `REACT_APP_API_BASE_URL` = your Render URL, with no trailing slash and no `/api`. The
     build fails on purpose if this is missing.
   - Optional Firebase web config: `REACT_APP_FIREBASE_API_KEY`,
     `REACT_APP_FIREBASE_AUTH_DOMAIN`, `REACT_APP_FIREBASE_PROJECT_ID`,
     `REACT_APP_FIREBASE_APP_ID` (public identifiers, not secrets).
4. Deploy, and note the URL (for example `https://bengaluru-pulse.vercel.app`).
5. These variables are baked in at build time, so change them and then **Redeploy**.

## 4. Connect the two

- On Render, set `CORS_ORIGINS` to both Vercel URLs, for example
  `https://bengaluru-pulse.vercel.app,https://bengaluru-pulse-admin.vercel.app`, then save.
  Render redeploys.
- If you use Firebase, add both Vercel domains under Firebase console → Authentication →
  Settings → **Authorized domains**.

## 5. Collector (optional, needs a TomTom key for traffic)

GitHub repository → Settings → Secrets and variables → Actions → add:

- `COLLECTOR_DATABASE_URL`: the Render database's **External Database URL**
- `TOMTOM_API_KEY`: the same key as on Render

Then go to Actions → "Traffic collector (scheduled)" → **Run workflow** once, and check that the log
reports stored observations. Until `COLLECTOR_DATABASE_URL` exists, the job skips itself.

## 6. Checks before calling it deployed

1. `https://<api>/health` returns `status: ok`.
2. `https://<api>/health/ready` shows `database: ok` and `osrm_car: ok`.
3. Open the Vercel URL, register, sign in, and plan a car route. You should see routes on the map.
4. The browser console shows no CORS errors.
5. The admin URL loads and signs in with the admin account.
